## 1. 需求背景与目标

| 项目 | 说明 |
|---|---|
| 背景 | 当前升级流程是"前台执行"：检查更新 → 停后端 → checkout → 安装依赖 → 构建（**GUI 中断数分钟**）→ 重启。且首次运行需要 git clone 才能用。 |
| 目标 1 | **首版内置**：打包时把一版可运行的 DeepSeek Harness 集成进 .app，首次打开**直接可用**，不做 git |
| 目标 2 | **后台自动升级**：应用在后台检测到新版本后，自动 git 拉取最新版并**后台构建**，全程不影响前台 GUI 使用 |
| 目标 3 | **就绪后提示**：构建完成后前台出现提示（不打断），用户点击"更新"才替换 |
| 目标 4 | **替换 + 重启生效**：点击更新后替换为已构建的新版本，提示需要重启生效 |
| 总原则 | **升级全过程不打断前台正常使用**（构建期间 GUI 继续用旧版本） |

## 2. 用户故事

1. 首次安装后，我打开应用立即能用（内置版本），不需要等 git clone。
2. 应用在后台发现新版本，自己拉代码、自己构建（我该干嘛干嘛，GUI 不受影响）。
3. 构建好了，应用右下角轻轻提示我"新版本 vX 已就绪"。
4. 我点"更新"，应用替换到新版本并告诉我需要重启生效；我点重启，新版本开始工作。
5. 我也可以随时手动"立即检查更新"，或忽略提示，完全不更新也行。

## 3. 升级状态机（用户视角）

```
[空闲] --启动后20s/每6h/手动检查--> [检测中](后台, 前台无感)
   ├─ 无新版本 ──────────────────────────────> [空闲]（静默）
   └─ 有新版本 --> [构建中](后台, 前台无感, 可能几分钟)
        ├─ 构建失败 --> [失败](提示可重试) --> [空闲]
        └─ 构建完成 --> [就绪]（前台提示"新版本 vX 已就绪"）
             ├─ 用户忽略 --> [空闲]（提示消失, 下次检测再提示）
             └─ 用户点击"更新" --> [替换中](短暂停后端~1s) --> [已更新, 待重启]
                  └─ 用户点"重启" --> 应用重启 --> 新版本生效
```

## 4. 功能需求

### FR-1 内置首版（Bundle）
- 打包时把**构建好的完整 checkout**（源码 + 依赖 + 构建产物 + git 元数据）集成进 `.app`（`Resources/harness-bundle/`）。
- 首次启动：解包到 `~/dsh-app/harness`（本地复制，非 git），解包完成后直接启动后端。
- 解包期间显示进度窗口（本地复制约 1–2 分钟，远快于 git clone）。

### FR-2 后台检测与自动构建
- 触发时机：启动后 20s 自动一次；之后每 6 小时一次；菜单"立即检查更新"手动触发。
- 检测：`git fetch`（只更新远程引用，**不动运行中的工作树**）→ 与当前版本对比（默认 tag 通道）。
- 有新版本：自动创建**构建区**（git worktree，复用对象库），后台执行 `pnpm install` + `pnpm build`。
- **前台零感知**：构建期间 GUI 继续用旧版本正常使用；构建进度只在"关于"或提示条中可查，不弹窗打扰。
- 失败处理：网络失败静默重试；构建失败清理构建区，前台提示可重试；均不影响当前使用。

### FR-3 就绪提示（前台）
- 构建完成后，页面右下角出现**非模态提示条**："新版本 vX 已就绪" + 按钮 [立即更新] [忽略]。
- 提示条为壳层注入（不动 harness 前端源码），不打断当前操作，可随时关闭（忽略）。
- "关于"面板显示当前版本 / 待更新版本 / 构建状态。

### FR-4 更新替换与重启生效
- 用户点击"立即更新"：停止后端（约 1 秒）→ **原子替换**目录（旧→备份，新→运行位，失败自动回滚）→ 提示"新版本已就位，需要重启应用生效"。
- 用户点击"重启"：应用完整重启（后端 + 窗口），新版本生效。
- 替换失败自动回滚到旧版本，应用继续可用。

### FR-5 兼容既有功能
- 菜单、⌘U 手动检查、关于、日志、优雅退出不变。
- 数据目录 `~/.dsh`（sessions/storages/profiles）不受目录替换影响（本就不在 checkout 内）。
- 手动"重启后端"（⌘⇧R）继续可用。

## 5. 验收标准

1. 全新机器（或删除 `~/dsh-app`）：首次打开应用 → 进度窗口解包内置版 → 直接可用（**无 git 过程**）。
2. 模拟远程有新版本：应用在后台自动 fetch + 构建，期间 GUI 正常使用（会话、操作无中断）。
3. 构建完成后出现"新版本 vX 已就绪"提示条；忽略后不影响使用。
4. 点击"更新"→ 后端短暂重启 → 提示重启生效 → 重启后为新版本。
5. 模拟构建失败/断网：应用保持旧版本可用，提示可重试，无崩溃。
6. 替换失败（模拟）：自动回滚，应用可用。
7. 现有功能回归：⌘U、重启后端、关于、升级进度窗口、优雅退出、冒烟测试。

## 6. 决策记录（已确认 2026-08-18）

| 决策点 | 结论 |
|---|---|
| 内置体积策略 | **全量内置**（node_modules 完整；.app 约 1.5G；体积优化留后续） |
| 重启生效方式 | **手动确认重启**：点击更新 → 替换 + 重启后端（等效生效，GUI 不中断）→ 弹窗"新版本已生效，建议重启应用" [立即重启] / [稍后] |
| 提示条位置 | **右下角浮条**（非模态，可忽略） |
| 更新通道 | 沿用 tag 通道（`dsh-v*` 稳定标签），设置可切 master |
| 图标样式 | **A：透明底蓝鲸**（当前样式，无需更换） |
