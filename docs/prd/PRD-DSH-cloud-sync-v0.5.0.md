## 1. 背景与目标

### 1.1 背景

当前 dsh-desktop 的**所有数据都在本机**：

- 会话（对话记录）：`~/.dsh/sessions/<项目>/<会话>/session.jsonl.zstd`（JSONL + zstd 帧流，append-only）；
- 项目（工作区）元数据：`~/.dsh/storages/workspace.json`（workspace 记录：ID/路径/标题/会话列表/时间戳）、`session_projcache.json`（缓存）；
- 配置与凭据：`~/.dsh/settings.yaml`、`.credentials.yaml`（含 API Key，敏感）。

**现状痛点**：

| 痛点 | 说明 |
|------|------|
| 换机/多机无法续聊 | 会话、项目归属全部锁在本机 `~/.dsh`，换机器后历史会话与项目列表不可见 |
| 手工迁移笨拙 | 只能整目录拷贝，且 workspace 里是绝对路径（`/Users/...`），拷贝到另一台机器路径对不上 |
| 无任何云能力 | 应用里的"云端"目前只用于升级（GitHub Releases/jsDelivr），与用户数据无关 |
| 数据安全焦虑 | 会话内容含提示词/代码/结果，若做同步必须先解决加密与凭据保护 |

### 1.2 目标

| 目标 | 说明 | 成功标志 |
|------|------|----------|
| 会话云端同步 | 本地会话可推送到云端、从云端拉取到其他设备，跨设备查看/续聊 | 设备 A 的会话在设备 B 上可见且可正常打开；增量同步（只传新帧） |
| 项目（workspace）同步 | 项目清单与会话归属跨设备一致，路径差异可映射 | 设备 B 上 workspace 列表与 A 一致，打开会话时正确映射到本机路径 |
| 全程加密 | 同步数据默认加密，云端/仓库里看不到明文 | 仓库内容为密文；密钥保存在系统钥匙串 |
| 增量与低流量 | 会话是 append-only 日志，只同步新增部分 | 二次同步仅传输新帧，不整文件重传 |
| 不动 harness | 同步引擎在壳层，不修改 harness 会话格式 | harness 升级/重建不影响同步；同步不写 harness 未知文件 |

### 1.3 非目标（本版本不做）

- **自动定时同步**（v0.6.0）：本版为手动 + 启动拉取；
- **双端活跃冲突自动合并**（v0.6.0）：本版冲突时提示用户选择并保留副本；
- **项目业务文件同步**（代码/文档本身）：那是 git/网盘职责，dsh 只同步 workspace 元数据；
- **多设备实时在线/协作**：同步是"拉取-合并-推送"模型，非实时；
- **自建同步服务器**：本版复用 GitHub 私有仓库做载体，零部署；
- **profiles/（web 插件配置）同步**：机器相关，后续版本再评估。

## 2. 用户故事

1. **多机用户（主力场景）**：在家用 Mac 上聊完一个需求 → 到公司 Windows 打开应用 → 「立即同步」→ 会话列表出现昨晚的对话 → 打开继续。
2. **换机用户**：新机器装好应用 → 设置同步（GitHub 仓库 + 口令）→ 启动时自动拉取 → 所有历史会话与项目列表回归。
3. **隐私敏感用户**：设置里开启加密并设置口令 → 云端仓库里所有内容均为密文，即使仓库泄露也无法阅读。
4. **路径迁移用户**：A 机器 workspace 指向 `/Users/alice/proj`，B 机器是 `D:\work\proj` → 同步时 B 端提示"检测到未映射路径"，选择映射后会话正常打开。
5. **冲突用户**：两台设备同时修改同一会话 → 同步时检测到双向更新 → 弹窗选择"以本设备为准/以云端为准"，被覆盖方保留 `.conflict-<时间戳>` 副本。

## 3. 功能需求（FR）

> 优先级：P0=核心可用；P1=重要增强；P2=后续版本。

### 3.1 同步框架（FR-S1）

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| FR-S1.1 | 同步开关与配置 | P0 | 设置页新增「同步」分类：启用开关、同步载体配置（GitHub 私有仓库 + Token）、加密口令、设备名 |
| FR-S1.2 | 立即同步 | P0 | 菜单「立即同步」（⌘⇧S）与设置页按钮均触发全量同步（先拉后推） |
| FR-S1.3 | 启动拉取 | P1 | 应用启动且已启用同步时，后台自动拉取一次（可关闭） |
| FR-S1.4 | 同步状态可见 | P0 | 设置页显示：上次同步时间、本次结果（推送/拉取/冲突数）、失败原因；同步中显示进度 |
| FR-S1.5 | Provider 抽象 | P1 | 同步载体抽象为接口；本版实现 GitHub 私有仓库，后续可加网盘/自建服务 |

### 3.2 会话同步（FR-S2）

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| FR-S2.1 | 会话推送 | P0 | 本地会话上传云端；已同步过的会话只传新增 zstd 帧（增量） |
| FR-S2.2 | 会话拉取 | P0 | 云端会话下载到本地对应项目目录，harness 可正常打开（seq 连续、帧完整） |
| FR-S2.3 | 会话删除同步 | P1 | 本地删除会话 → 云端标记删除（墓碑），其他设备拉取后移除 |
| FR-S2.4 | 归档状态同步 | P1 | `archivedSessionIds` 随 workspace 数据同步 |
| FR-S2.5 | 不完整帧保护 | P0 | 同步时若发现文件尾是未写完的帧（harness 正在写），跳过该帧，下次同步再补 |

### 3.3 项目（workspace）同步（FR-S3）

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| FR-S3.1 | workspace 清单同步 | P0 | `workspace.json`（ID/标题/会话列表/时间戳）跨设备一致 |
| FR-S3.2 | 路径映射 | P0 | 远端 path 在本机不存在时，提示用户映射到本机路径；映射结果记忆并复用 |
| FR-S3.3 | 会话-项目归属恢复 | P0 | 拉取后会话出现在正确的 workspace 下（按 workspace 的 sessionIds + 映射后的路径） |
| FR-S3.4 | 缓存不同步 | P1 | `session_projcache.json`（可重建缓存）不同步，拉取后由 harness 自动重建 |

### 3.4 安全与隐私（FR-S4）

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| FR-S4.1 | 同步数据加密 | P0 | 会话/workspace 同步内容 AES-256-GCM 加密；云端文件为密文（按帧加密，增量可独立解密） |
| FR-S4.2 | 密钥保护 | P0 | 加密密钥存系统钥匙串（Electron `safeStorage`），口令不落盘明文 |
| FR-S4.3 | 敏感文件永不入云 | P0 | `.credentials.yaml`、`.anonymous-user-id`、`settings.yaml`、`profiles/` 默认不同步（黑名单） |
| FR-S4.4 | Token 保护 | P0 | GitHub Token 存入钥匙串，设置页不回显明文 |

### 3.5 冲突与异常（FR-S5）

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| FR-S5.1 | 会话双向更新检测 | P0 | 同步时对比本地/云端已提交字节，双方都有未提交更新 → 判冲突 |
| FR-S5.2 | 冲突处理 | P0 | 弹窗让用户选择保留方；被覆盖方在本地保留 `.conflict-<ts>` 副本，不静默丢数据 |
| FR-S5.3 | 格式不兼容保护 | P1 | 会话格式版本（`SESSION_FORMAT_VERSION`）不匹配时跳过该会话并提示，不写入未知格式 |
| FR-S5.4 | 网络/Token 失败可恢复 | P0 | 任一步失败不破坏本地数据，下次同步可重试（幂等） |

## 4. 验收标准

1. 设备 A 启用同步并推送 → 设备 B 配置同一仓库 → 启动拉取：B 端会话列表出现 A 的会话，打开正常（无 seq 错误）。
2. 二次同步：A 新增一条会话消息 → 同步 → 云端仅新增对应帧（抓包/仓库 diff 验证增量），B 拉取后看到新消息。
3. 路径迁移：A 的 workspace 路径在 B 上不存在 → B 同步时提示映射 → 映射后会话打开成功；再次同步无需重复映射。
4. 加密验证：仓库内 `*.zstd` 与 workspace 文件均为密文，无明文 JSONL/文本。
5. 冲突：A、B 各自离线修改同一会话 → 各自同步 → 第二次同步提示冲突，选择后数据不丢失（有 conflict 副本）。
6. 敏感文件：仓库内不存在 `.credentials.yaml`、`settings.yaml`、`.anonymous-user-id` 等黑名单文件。
7. 回归：同步开关关闭时行为与现状完全一致；同步过程中 harness 会话读写不受影响（无损坏、无卡顿）。

## 5. 决策记录（草案，待评审确认）

| 决策点 | 结论（草案） | 说明 |
|--------|--------------|------|
| 同步载体 | GitHub 私有仓库（v0.5.0） | 零部署、已有 GitHub 生态（升级即用）；抽象 Provider 接口，后续可加网盘/自建 |
| 同步引擎位置 | 壳层（`src/sync.ts`） | 壳是 Electron 主进程，有网络/钥匙串/UI 能力，独立于 harness 生命周期；不改 harness 一行 |
| 会话同步粒度 | 文件字节级 + zstd 帧增量 | 会话文件是 append-only 帧流（完整帧拼接），增量=只传新帧字节；壳端只需识别帧边界，不解码 |
| 合并策略 | 会话 LWW（最后提交者）+ 冲突提示 | 会话主要在单设备活跃、跨设备低频读；自动 seq 重编号合并留 v0.6.0 |
| workspace 合并 | 整文件 LWW + 冲突副本 | 跨设备 sessionIds 集合合并留 v0.6.0 |
| 路径映射 | 远端存各设备 path 字典，拉取时按设备查/提示 | workspace 存的是 `fs.realpath` 绝对路径，跨设备必须映射 |
| 加密 | 默认开启，AES-256-GCM 按帧加密 | 密钥经口令派生后存系统钥匙串（safeStorage）；无口令也可用（仅加密元数据） |
| 冲突保留 | 本地保留 `.conflict-<ts>` 副本 | 绝不静默覆盖 |
| 触发方式 | 手动（⌘⇧S/按钮）+ 启动拉取 | 自动定时同步 v0.6.0 |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| harness 活跃写会话时壳读文件 → 读到半帧 | 拉取/推送损坏数据 | 读前两次 stat 校验大小稳定；文件尾不完整帧跳过（zstd 帧有 magic+checksum 可识别）；harness 自身有 torn-tail 修复兜底 |
| workspace path 是绝对路径，跨设备必然不同 | 会话打开失败 | 路径映射字典 + 首次提示；workspace 记录以 ID 为主键，路径只作展示/关联 |
| 会话格式随 harness 升级变化 | 写入未知格式损坏数据 | 同步前校验 `SESSION_FORMAT_VERSION`/header 版本，不匹配则跳过并提示 |
| GitHub Token 泄露 | 仓库内容被读 | 内容已加密（默认开启）；Token 存钥匙串；README 提示用最小权限 fine-grained token |
| 口令遗忘 | 无法解密 | 设置页支持重设口令（旧口令解密→新口令重加密）；提示用户备份口令 |
| 多设备并发写同一会话 | 双向更新 | LWW + 冲突弹窗 + conflict 副本，不静默丢数据 |
| 仓库被误删/被清空 | 数据丢失 | 同步前本地始终是权威副本（pull 只追加不删除）；删除同步（墓碑）默认关闭/二次确认 |
| 同步拖慢启动 | 体验变差 | 启动拉取在后台异步执行，不阻塞窗口；大文件增量传输 |
