## 1. 背景与目标定义

### 1.1 背景

DeepSeek Harness 的 Web GUI 目前通过浏览器访问（`dsh --profile web` 起本地服务）。桌面壳（`dsh-desktop`）以 Electron 应用形式封装该 GUI：**用系统 Node 以子进程方式启动后端，原生窗口承载页面，并提供 git 托管的自助升级闭环**。壳层遵循"**零前端改动**"原则——所有桌面能力（沉浸式窗口、拖拽区、更新提示条）由 Electron 主进程/preload 注入实现，harness 前端与后端源码零修改。

### 1.2 目标定义

| 目标 | 说明 | 成功标志 |
|------|------|----------|
| 桌面化封装 | 双击即用的 macOS 应用，承载 Harness GUI | .app 可运行，GUI 功能与浏览器一致 |
| 沉浸式窗口 | 无标题栏 + 原生红绿灯 + 顶部拖拽区 | 页面铺满窗口、可拖拽、红绿灯原生交互 |
| 品牌化 | DeepSeek 官方图标、本地化系统菜单 | Dock 图标正确；菜单语言跟随 dsh-app 语种 |
| 自助升级 | 首版内置 + 后台检测构建 + 前台提示 + 替换重启 | 升级全程不打断前台使用 |
| 可维护 | 壳与 harness 解耦，升级不碰壳 | 目录/状态机/回滚清晰，失败可恢复 |

### 1.3 非目标（本版本不做）

- Windows / Linux 打包目标（后续版本）
- Electron 壳二进制的自更新（electron-updater；当前壳更新 = 重新打包安装）
- 托盘常驻、多窗口、系统通知中心集成（后续版本）
- harness 前端/后端源码的任何改动

## 2. 目标用户与使用场景

| 用户 | 诉求 | 关键场景 |
|------|------|----------|
| **深度使用者** | 原生桌面体验、后台自动升级 | 双击打开即用；后台构建新版期间正常使用；一键更新 |
| **开发者**（使用 Harness 写代码） | agent 直接在 checkout 上工作 | 运行区即 git 仓库，agent 可改源码；升级前提示处理未提交改动 |
| **多语言用户** | 菜单语言跟随 dsh-app | 在 GUI 设置里切换中/英文，系统菜单同步切换 |

典型场景：
1. **场景 A：首次使用** — 全新机器打开 .app → 解包内置版 → 直接可用（无 git、无网络）
2. **场景 B：后台升级** — 应用在后台发现新版本并构建，用户无感；就绪后右下角提示，点击更新、重启生效
3. **场景 C：沉浸式使用** — 无标题栏窗口，红绿灯原生交互，顶部拖拽
4. **场景 D：语种切换** — GUI 设置切到 English，系统菜单立即变英文

## 4. 非功能需求（NFR）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| NFR-1 | 升级不打断前台 | 构建期间 GUI 正常使用；替换仅闪断 ~1s |
| NFR-2 | 失败可恢复 | 构建失败清理构建区；替换失败自动回滚；崩溃后基于状态文件恢复 |
| NFR-3 | 磁盘占用 | 构建区安装期间额外 ~1.2G，替换后清理旧区（峰值 ~2.4G，可接受） |
| NFR-4 | 安全 | 页面仅 loopback；IPC 校验 sender；拖拽区不泄露 Node 权限（contextIsolation+sandbox） |
| NFR-5 | 数据安全 | 壳升级/替换不触碰 `~/.dsh`（sessions/storages/profiles 在 DSH_HOME） |
| NFR-6 | 打包体积 | .app ≈ 568M（含内置 bundle）；zip ≈ 520M（全量内置，裁剪为后续优化） |
| NFR-7 | 跨设备可构建 | 构建工具（git/node≥22/pnpm≥11）发现不依赖特定机器：settings/env pin > PATH > 平台目录 > corepack > npx；缺失时给出可操作报错 |

## 5. 系统架构与集成

- **进程**：Electron 主进程（壳）→ spawn 系统 Node 后端子进程 → 主窗口 `loadURL(http://127.0.0.1:<port>)`
- **零前端改动**：拖拽区、更新提示条由 preload 注入 DOM；红绿灯为系统原生
- **目录**：`~/dsh-app/{harness, harness-new, harness-old, update-state.json, settings.json, env, logs}`；`~/.dsh`（后端数据）
- **升级管线**：idle → checking（fetch）→ building（archive+install+build）→ ready（toast）→ applying（替换）→ applied →（重启）→ idle
- **语种链路**：`~/.dsh/settings.yaml` → `locale.preference` → 主进程读 → 构建菜单文案；fs.watch 监听变化重建
- 详见技术方案 [dsh-desktop-shell-v0.1.0](../technical/dsh-desktop-shell-v0.1.0.md)

## 6. 约束与限制（现实性说明）

- 升级构建依赖本机 git / pnpm（≥11）/ node（≥22.19）；Finder 启动时 PATH 由壳补充
- 内置 bundle 为全量 node_modules（约 320M 压缩），.app 较大；裁剪为后续优化项
- 未签名应用首次打开需右键 → 打开（个人自用可接受；分发需签名/公证）
- macOS 仅 x64（Intel）目标（当前机器架构）
- 首次解包约 1–2 分钟（本地复制/解压，非网络）

## 7. 验收标准与上线流程

### 7.1 已实现并通过自动验证

1. 壳 + 后端集成：`SMOKE_OK`、`SMOKE_DRAG_REGION OK`、优雅退出无孤儿进程
2. 首次运行（内置解包）：空 `DSH_APP_HOME` 下解包 → 后端启动（无 git）
3. 升级闭环（fake remote 全链路）：检测 → 后台构建（前台无感）→ ready → toast（CDP 验证）→ 替换 → 新版生效 → 自动再检测判定最新
4. 单元：checkForUpdates / buildUpdate / applyBuiltUpdate / 回滚分支

- [ ] 点更新 → 替换 → 新版生效 → 弹窗重启

- [ ] **菜单跟随 dsh-app 语种切换（新需求，实施后验收）**

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 后台构建与手动操作并发 | 状态错乱 | 状态机单例串行 + 单实例锁 |
| 替换中途崩溃 | 应用不可用 | update-state.json + 启动自动回滚 |
| 语种文件解析失败/被外部修改 | 菜单语言不对 | 容错默认跟随系统；fs.watch 失败不影响启动 |
| 内置体积大 | 打包/分发慢 | 全量先跑通，裁剪（prod-only）为后续优化 |
| 桌面环境受限（Finder PATH） | 构建失败 | PATH 补充（pnpm 11 工具链目录） |

## 10. 术语表
